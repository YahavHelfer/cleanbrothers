# Phase 3D1 — מיפוי דף הבית וגבולות העריכה (מקומי בלבד)

## מצב התחלתי

הנתיב `/` נבנה כיום מ־`src/app/(site)/page.tsx`. הוא סטטי כברירת מחדל. ה־Navbar, ה־Footer ו־LocalBusiness JSON-LD מורכבים ב־layout ממסמכי Site Chrome נפרדים. שירותי CRM, Google/Meta, הסכמת cookies, שיוך WhatsApp ומעקב טלפוני נשארים בקוד. אין שינוי לענן בשלב זה.

## מדיניות

דף הבית הוא מסמך `home` אחד, בנתיב `/` וב־canonical קבוע. Hero גלוי אחד נדרש עבור H1. מקטעים ייעודיים הם singleton כדי למנוע שכפול לא הגיוני; Rich Text ומבצע יכולים להתווסף לפי חוקי הבלוקים. מצב Preview מדויק משתמש בטיוטת דף הבית אך ב־Site Chrome המפורסם בלבד. פונקציות לידים, חיוג, WhatsApp ומעקב המרות אינן פעילות בתצוגה המקדימה. רשימת השירותים בכרטיסי הבית משתמשת בזהות שירות קבועה, אך המלל שלה שונה ממלל עמודי השירות ולכן נשמר כמסמך עריכה ייעודי לבית. ניווט/כותרת עליונה/Footer אינם מועתקים לגרסת הבית.

בשער הציבורי, משתני שירותים/עמודים/Site Chrome אינם מפעילים את הבית. נדרשים מקור בית מפורש, allowlist מדויק של `home`, סביבת Preview, ענף ופרויקט מאושרים ופרויקט Supabase CMS המאושר. Production נשאר סטטי. ב־Preview המאושר אפשר לבצע בחירת מקור בזמן בקשה כדי למנוע alias ישן, אך כל עוד השער הספציפי סגור התוכן נשאר סטטי.

## מימוש מקומי וגבולות פרסום

- `home` הוא מסמך page בעל UUID קבוע ו־schemaVersion 12; הנתיב וה־canonical הם `/` ואינם ניתנים לעריכה. הוא משתמש בטבלאות הגרסאות, הבלוקים, האירועים ומצב הפרסום הקיימות. Hero אחד גלוי חייב להיות ראשון; כל סוג מקטע ייעודי אחר מופיע לכל היותר פעם אחת.
- מיגרציית `20260927150000_cms_homepage_blocks.sql` מרחיבה את האילוצים והפונקציות הקיימות, מוסיפה RPC נפרד לקריאת גרסה מדויקת על ידי מנהל AAL2 ו־RPC ציבורי ללא ארגומנטים שמחזיר רק גרסה מפורסמת, בלוקים גלויים והפניות מדיה/מבצע נעולות. היא לא הוחלה בענן.
- `npm run cms:import-home` פועל רק מול ערימת Supabase מקומית מבודדת. הוא מאמת את הבתים וה־SHA-256 של נכסי התמונה הקיימים לפני ייבוא; הפעלה חוזרת משאירה Revision 1, מצביעי הפרסום וההפניות ללא שינוי.
- העורך משתמש בבקרות RTL סגורות לטקסט, גרסאות מדיה, זהויות שירות וסדר המקטעים. שמירה יוצרת גרסה חדשה בלבד; פרסום דורש אישור מפורש ומעדכן מצביע תחת נעילת שורה; שחזור יוצר טיוטה חדשה. בדיקת generation + base revision מונעת דריסה בידי עורך ישן.
- כרטיסי השירות משתמשים במפתח שירות קבוע ובמלל ייעודי לעמוד הבית, משום שהמלל הנוכחי שונה מזה של עמודי השירות. ה־URL וזהות ה־CRM ממשיכים להגיע מקוד השירותים. מחשבון המחיר שומר בקוד את האפשרויות, נוסחאות, טווחי המחיר ופעולת WhatsApp; העורך משנה רק מלל הקדמה ונראות.
- תמונת ה־Hero וארבעת זוגות לפני/אחרי נקשרים לגרסאות Media Library בלתי משתנות. בלוק מבצע אופציונלי נקשר ל־UUID של גרסת מבצע מדויקת, ונדרש שהגרסה הזאת פורסמה לפני פרסום הבית. אין תזמון מבצעים בשלב זה.
- תצוגת גרסה מדויקת משתמשת באתר Chrome המפורסם; CTA של חיוג ו־WhatsApp מוצגים ללא פעולה, ללא סמן מעקב שיחות וללא קריאת API. ה־FAQ הגלוי ו־FAQ JSON-LD נבנים מאותה גרסת בית; FAQ מוסתר אינו נכנס לשניהם. LocalBusiness/Service JSON-LD מקבל את אותו snapshot מפורסם של Global Settings שממנו מורכב מעטפת האתר.
- `CMS_HOME_SOURCE=published` ו־`CMS_HOME_ALLOWLIST=home` הם שני שערים עצמאיים, בנוסף לפרויקט/ענף/Preview/Supabase המאושרים. כל ערך wildcard או סביבת Production משאירים את דף הבית סטטי. פריסת Preview מאושרת יכולה לבצע בחירת מקור בזמן בקשה גם כאשר השער כבוי, כדי שלא יוגש alias סטטי ישן; אין שינוי גלובלי באחסון האתר.
- הערכת שקילות ציבורית משווה את כל 16 הנתיבים ל־baseline המאושר. בדף הבית מנורמלים רק מזהי `useId` האטומים של React לפי סדר ההופעה, תוך בדיקת אותו סדר, אותה כמות ואותן הפניות ARIA; מלל, HTML, קישורים, תמונות, מטא־דאטה ו־JSON-LD אינם מנורמלים.
